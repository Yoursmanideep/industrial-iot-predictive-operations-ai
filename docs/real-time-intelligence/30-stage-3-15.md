# 30 — Real-Time Operational Intelligence

## Scope

Stage 3.15 connects the deterministic simulator to the Microsoft Fabric Real-Time Intelligence stack.

## Current Fabric pattern

Fabric Eventstream can ingest real-time data, apply transformations, and route the stream to destinations such as Eventhouse and Activator. Eventhouse is intended for streaming/time-series analytics, while Activator evaluates conditions and initiates actions.

## End-to-end flow

```text
Simulator LIVE
    ↓
Validated event
    ↓
Custom Endpoint
    ↓
Eventstream
    ├── Eventhouse: IndustrialIoTEvent
    │       ↓
    │     KQL
    │       ↓
    │     Real-Time Dashboard
    │
    └── Activator
            ↓
         Power Automate
            ↓
      Incident / Maintenance / Production Loss workflow
```

## Live simulator bridge

`industrial-sim --publish-eventstream` enables Eventstream publication.

Credentials are loaded only from:

- `FABRIC_EVENTSTREAM_CONNECTION_STRING`, or
- `FABRIC_EVENTSTREAM_FQDN` + `FABRIC_EVENTSTREAM_ENTITY_NAME` with Entra ID credentials available to the runtime.

The existing simulator JSONL output remains active, so live publication does not eliminate replayable durable simulator output.

## Eventhouse

`IndustrialIoTEvent` preserves the canonical event envelope plus operational identifiers and the original JSON payload.

KQL functions derive real-time views from this single hot event table instead of duplicating all events across multiple hot tables.

## Real-time metrics

The KQL layer provides:

- latest machine telemetry
- recent critical incidents
- machine risk score
- 15-minute production summary
- production loss events
- plant-level real-time KPI context
- stream ingestion-lag diagnostics

The machine risk score is an operational heuristic, not the ML predictive-maintenance model. Its thresholds are explicitly configurable synthetic defaults.

## Activator

Current trigger contract contains six rules:

- critical machine fault
- critical alarm
- communication loss
- critical temperature
- critical vibration
- production loss

Rules are scoped by machine and use `event_id` as the event identity for downstream idempotency.

## Power Automate

Critical incidents create an operational incident record and maintenance handoff, notify Operations and Reliability, and use retries plus deduplication.

Communication-loss incidents are escalated after the configured review window when still open.

Production-loss events create a production-control follow-up work item.

## Dataverse

The repository defines the logical schema for:

- `IndustrialIoTIncident`
- `MaintenanceWorkItem`
- `ProductionLossWorkItem`

Actual Dataverse table creation, environment connection references, security roles and connector bindings remain deployment-time configuration.

## Monitoring

Fabric Eventstream provides data-insights/runtime-log monitoring, and Eventhouse has a monitoring experience for usage and performance.

These platform monitoring capabilities are part of the production operationalization step after resource deployment.

## Runtime boundary

The source-controlled layer is complete.

Actual runtime proof still requires a Fabric workspace with the Eventstream/Eventhouse/Activator/Power Automate connections bound. No live Fabric execution is claimed from the Git repository alone.
