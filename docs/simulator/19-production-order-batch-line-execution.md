# 19 — Production Order, Batch and Line Execution Engine

## Scope

Stage 3.6 converts machine capacity and scenario impact into manufacturing execution.

The execution model is:

Production Order → Batch → Route → Line Bottleneck → Unit Produced → Loss / Completion.

## Product routes

Each of the 12 seeded products has a deterministic machine-type route.

Examples include:

- Motor Assemblies: CNC → ROB → CON → INS → PKG → PAL
- Pump Systems: CNC → HPR → ROB → INS → PKG → PAL
- Drive Systems: CNC → ROB → INS → PKG → PAL
- Fluid Control: CNC → HPR → INS → PKG → PAL
- Machined Components: CNC → INS → PKG → PAL
- Drive Components: CNC → ROB → INS → PKG → PAL

Every route is validated against every one of the 15 production lines.

## Order identity

Production orders use deterministic UUIDv5-style identity derived from:

- simulator run
- plant
- line
- planned start
- production sequence

The same inputs therefore reproduce the same order ID.

## Batch identity

Batch IDs are derived from the production order and batch sequence.

Batch quantities are partitioned deterministically and must sum exactly to the order planned quantity.

## Line execution

A product route requires one machine for each route step.

The line bottleneck is the minimum available capacity across the route machines.

Scenario production multipliers are applied to the route machine capacities.

The execution engine also retains nominal bottleneck capacity so production slowdown can be measured against the expected line capacity.

## Production accounting

Each execution interval can create a UnitProduced event.

The accounting invariant remains:

good quantity + rejected quantity ≤ actual quantity.

Rejected quantity is created from the product quality baseline multiplied by the scenario quality effect. Actual observed quality-defect events will be generated by the dedicated quality engine in a later stage.

## Pause and resume

A line can be explicitly paused with a governed pause-reason code and later resumed.

Examples:

- MACHINE_FAULT
- MATERIAL_STARVATION
- PLANNED_CHANGEOVER
- QUALITY_HOLD
- OPERATOR_SHORTAGE
- UTILITY_INTERRUPTION

Pause/resume is event-driven and preserves causation links.

## Production losses

Two execution losses are currently supported:

SLOWDOWN:
actual bottleneck rate is below nominal bottleneck capacity.

DOWNTIME:
the route is unavailable because a required machine is unavailable.

Loss records carry reason, category, quantity/duration and optional machine-fault linkage.

## Completion lifecycle

Order lifecycle:

CREATED → RELEASED → STARTED → IN_PROGRESS → COMPLETED

Batch lifecycle:

CREATED → STARTED → IN_PROGRESS → COMPLETED

PAUSED can interrupt an active batch and later return it to IN_PROGRESS.

## Contract alignment

The implementation uses the existing production-event schema and controlled loss categories/reason codes.

Production events carry simulator lineage, correlation ID, causation ID and deterministic generation sequence.
